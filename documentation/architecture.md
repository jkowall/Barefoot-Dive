# Architecture

## Runtime

Barefoot Dive is a client-only React 19/TypeScript/Vite application. The browser PWA uses static assets and an explicitly registered production service worker from `vite-plugin-pwa`; registration is skipped when `Capacitor.isNativePlatform()` is true. Capacitor packages the same bundle for iOS and Android without running a service worker inside the native WebView. Development service-worker registration is intentionally disabled. There is no server, account, network calculation service, analytics, subscription, provider credential, or secret boundary. The app sends no email, runs no scheduled or background work, and embeds no agents, webhooks, or external automation.

## Calculation layers

`src/domain` defines branded units, defaults, validation, gas/cylinder types, diagnostics, and plan schemas. `src/domain/validation.ts` also owns the shared PPO₂ helpers (`gasPPO2`, `isBelowMinimumPPO2`, `isGasBreathable`, `isSwitchEligible`, `compareGasPreference`, `effectiveBailoutGases`) so the scheduler, validation, and the cave layer judge a gas the same way. `src/engine` contains the pure ZH-L16C (16 compartments) tissue model, GF ceilings, deterministic stop scheduler, event model, OC/CCR breathing strategies, gas switching, setpoint transitions, and exact-state CCR bailout. `src/gas` integrates surface-normalized gas use and reserve policy crossings. `src/calculations` contains the production functions behind the 11 named Tools capabilities and planner support flows.

`src/cave` is a local route/event/scenario layer over `calculateEventDivePlan`, not a second decompression engine. It models explicit penetration/exit legs, segment-level accessible-cylinder selection, stage drop/recovery state, operational turn thresholds, planned-turn minimum pressure, and lost-back-gas, lost-buddy, scooter-failure, stage-failure, and CCR-loop-failure scenarios. A ceiling-safe cave route must be explicitly represented and checked; cave output remains experimental pending qualified cave-diver review.

## Storage and UI

`src/storage` serializes versioned envelopes to `localStorage`. Tank Bank records carry timestamps and revisions. Saved plans clone normalized inputs, resolved equipment/gases, results, warnings, engine/convention metadata, and optional cave input/result snapshots. Recalculation appends a new record revision with parent lineage; it does not mutate the prior snapshot.

Reads validate the container before any record. Corrupt JSON, a value that is not a record list, or a `schemaVersion` other than `STORAGE_SCHEMA_VERSION` (1) fails the whole read, and every write through that store is refused, so a damaged or newer envelope is never overwritten. A legacy bare record array (a format no release has written) loads only when every record in it is valid, and becomes a current envelope on the next write; otherwise it fails the whole read in both stores. Record validation inside a current envelope then differs by store:

- **Saved Plans are all-or-nothing.** One invalid record fails the read with `STORAGE_INVALID`, and no write proceeds. Per-record quarantine is deliberately not applied here: immutable snapshot and lineage semantics are a protected area, and a partial library would need its own lineage rules.
- **Tank Bank quarantines per record** (`readEntries` and `writeEntries` in `src/storage/schema.ts`). A record must match the declared `TankRecord` and `Gas` field types: required strings and finite numbers present, optional fields absent or correctly typed. Unknown extra fields are ignored, and value ranges remain domain validation's job. The app's own Tank Bank write paths have written this full shape since the first release, so these checks quarantine only records the app did not write. Valid records load. Each invalid record yields a `STORAGE_RECORD_QUARANTINED` diagnostic with its zero-based position, its id and name when they are strings, and the failing field paths (for example `gas.oxygen`). A quarantined record is never listed, mutated, deleted, or offered to Plan, Cave, or Tools. Every later write copies its exact stored text back into the envelope, in the same order relative to the other records; its index changes only when an earlier record is deleted, and diagnostics returned by a write use the written positions. The text is never re-encoded, so values a JSON round trip would alter (an out-of-range number such as `1e400`, an integer beyond 2^53, a duplicate key, escapes, or whitespace) survive. A small scanner in `schema.ts` locates each record's text the way `JSON.parse` resolves the envelope (escaped keys, last duplicate `records` member) and must reproduce the parsed record; if it cannot (for example a hand-crafted record nested so deeply that re-serializing it for the check overflows the stack), the record's text is unmatched and every write is refused while that record remains. The store also refuses to write a record its own read would quarantine, so a caller that passes NaN or a missing field gets `STORAGE_INVALID` instead of a cylinder that disappears on the next read.

The stored format and schema version are unchanged by quarantine, so no migration exists for it. An older build reads the same format with its own looser all-or-nothing check: it loads the bank only when every record passes that check (so it can load a record this version quarantines only for a newly checked field: any `gas` field, or the type of `minimumPressureBar`, `role`, `archived`, or `archivedAt`) and otherwise rejects the whole bank as before.

`src/App.tsx` and the workspace components hold session drafts, matching calculated results, stale/source-change status, and navigation state. They pass normalized inputs to the pure calculation modules and render the returned values and diagnostics. `src/app/caveWorkspace.ts` defines the Cave session contract so its draft and matching result survive primary-workspace navigation. Its route legs record cylinder access and stages by gas draft key; `src/app/caveRoute.ts` pairs each plan cylinder with the gases `resolvePlanInput` assigns to it (the resolver maps `activeGasDrafts` one to one and in order), and builds the cave layer's cylinder-id route from that. A cylinder used by more than one gas (one Tank Bank record selected for several gases) builds no route: `normalizeCaveRoute` returns one blocking `ROUTE_CYLINDER_SHARED` error per such cylinder, and Cave reports "Cylinder shared" ahead of the shared `workspaceStatus` result unless a source is unavailable. Legs also record which gases the diver has set (`setGasKeys`), and `unsetGasNotices` returns one `ROUTE_GAS_ACCESS_UNSET` warning per gas an edited leg has not set. Cave derives those warnings from the current route rather than from the calculation, so setting a gas clears them at once, and it adds them to the saved snapshot's warnings. The stored route records cylinder ids only, so `buildRecalculation` cannot derive them again; it carries them into each recalculated revision, which reruns that route unchanged. Plan and Cave session drafts plus Tools inputs reset on reload; Tank Bank and Saved Plans persist through the storage codecs.

Plan and Cave resolve their drafts through the same pure function, `resolvePlanInput` in `src/app/planning.ts`, against a `TankBankSnapshot`: every loaded record (archived included) plus the id and name of each quarantined record, taken from its `STORAGE_RECORD_QUARANTINED` diagnostic, or the reason the bank could not be read (`tankBankSnapshot` builds it from a Tank Bank read). The result is discriminated. It carries a calculable `DivePlanInput` only when every active gas's selected Tank Bank cylinder loads. Otherwise it is `ok: false` with no input, `unavailableSources` (gas, cylinder id, reason, stored name when known, and the ad hoc gas and cylinder a detach would use), and one `TANK_SOURCE_UNAVAILABLE` error diagnostic per gas. Both workspaces map that result to a blocking "Source unavailable" status, so neither can calculate, recalculate, review, or save an input that substitutes ad hoc values for an unavailable record. Their status comes from one pure function, `workspaceStatus` in `src/app/workspaceStatus.ts`. While a source is unavailable, `invalidateForUnavailableSource` also marks the session's earlier calculation as superseded, so it cannot become current again without an explicit recalculation, even if the source returns unchanged.

`src/ui/profileChartModel.ts` converts emitted plan segments and reserve crossings into chart geometry, boundaries, and event markers. It interpolates planned depth inside each linear segment. `src/ui/ProfileChart.tsx` handles mouse, touch, and keyboard selection and renders only emitted phase, gas, setpoint, reserve, and endpoint-ceiling data. The chart does not calculate a new plan or infer continuous physiological or cylinder state.

`src/index.css` is the visual-system entry point; it only imports the sectioned stylesheets in `src/styles/` (tokens, base, shell, controls, layout, results, profile, pages, motion). Every color, size, and duration is a custom property declared in `src/styles/tokens.css`, and the IBM Plex Sans and Mono faces are bundled from `@fontsource` packages and precached by the service worker so the installed app renders identically offline. Gas ledger entries can additionally carry `gasOnly` and `requiredVolumeL` (gas-only planning) and `preBailoutDeductionL` (dil-out); all are optional, so stored snapshots stay readable without a schema migration. `src/app/recalculation.ts` reruns a saved plan from its stored normalized input exactly as stored, without defaults, so older records keep the behavior their missing fields imply; the store writes the result as a new revision. `src/app/runtimeRows.ts` is a presentation-only helper that folds consecutive identical stop segments into one runtime-table row; it never feeds a calculation.

The Tools workspace is a session-level UI over the production calculator functions. Its task categories and eleven named capabilities are documented in [`tools.md`](tools.md). Simple calculations are live and ephemeral. Emergency Gas debounces its explicit entered-schedule calculation, hides superseded output while updating, and enables Plan application only when the result signature matches the current input snapshot. CCR Simplified Bailout is bounded to one cylinder, and it is not a second planner or generated bailout engine. Tank Bank selections are copied into a session snapshot, with visible manual detachment. Plan application is an explicit allow-listed patch: Best Mix can change only the OC bottom-gas name/O2/He, SAC / RMV can change one selected RMV target, and OC Rock Bottom / Minimum Gas can change only OC rock-bottom assumptions.

Pressure types remain distinct through this boundary: ambient is absolute, cylinder pressure is gauge, and consumption uses gauge-pressure deltas. Best Mix and END policy identifiers, plus SAC / RMV input mode, belong in result assumptions so a policy or mode change can mark a result stale.

## Known risks and assumptions

- Current reference comparisons cover a limited set of profiles and formula fixtures. Cave workflows and compatibility-named presets remain experimental; [`reference-validation.md`](reference-validation.md) records the evidence boundary.
- Clearing browser or WebView storage removes Tank Bank and Saved Plan data. The product has no cloud backup or sync path.
- A Plan or Cave gas whose selected Tank Bank record is archived, deleted, quarantined, or unreadable is held out of every calculation until the diver chooses another cylinder or detaches it ([flow](flows.md#tank-bank-source-resolution-in-plan-and-cave)). Detaching uses the gas editor's ad hoc cylinder values, which are listed before the detach. Tank Bank "Use" copies only the gas name and mix, and choosing a source copies nothing, so those values are defaults or earlier entries rather than the record's and must be checked against the physical cylinder. Detaching or re-selecting also changes the gas's cylinder id; Cave route legs record access and stages by gas, so they follow the gas to its new cylinder instead of keeping the old id ([Cave flow](flows.md#cave-flow)). A gas that starts taking part after a leg's access was edited (switched back on, a travel gas, a new gas, or the other breathing mode's gases) starts inaccessible on that leg. Setup, Review, and saved snapshots flag it with a warning until the diver sets it, but the calculation is not blocked, so an unread warning still leaves that gas out of the plan on that leg. The gas-to-cylinder pairing relies on `resolvePlanInput` resolving the active gases one to one and in order; `src/app/caveRoute.test.ts` checks it against independently computed cylinder ids across breathing modes, gas switches, and source states.
- A green local build or CI run does not prove that Cloudflare serves the same revision. Release verification must compare the live asset hashes and headers after deployment.

## Build and release gates

`npm run lint`, `npm run test`, and `npm run build` are the baseline checks; `npm run check` runs all three. `npm run check:deploy` validates the Cloudflare Worker upload without publishing it. Cloudflare Workers Builds publishes the client-only web bundle from `main`; that delivery state does not change the scientific validation boundary. `npm run build:mobile` builds then runs Capacitor sync, and Playwright smoke/visual suites are separate browser gates. No signed or store-submitted native artifact is included.
